## 0. 一句话定位

一个**只作用于 educoder.net（头歌）**的 Edge 浏览器扩展（MV3）：解锁粘贴/复制、防剪贴板被篡改、答对自动下一关、编辑器美化（主题/字体/光标）。自用 + 分享给同学。

## 1. 运行形态与技术栈

| 项 | 值 | 说明 |
|---|---|---|
| 清单 | Manifest V3 | Edge / Chromium |
| 权限 | `scripting` + `activeTab` | 最小集：弹窗只对当前标签页执行脚本 |
| 宿主 | `*://*.educoder.net/*` | 只在头歌生效 |
| 内容脚本① | `允许粘贴.js`，`run_at: document_start`，`world: MAIN`，`all_frames: true` | 必须进页面主世界才能操作 `window.Monaco`、剪贴板对象；头歌编辑器在 iframe 里，所以 all_frames |
| 内容脚本② | `fonts.js`，`document_start`，隔离世界，`all_frames: true` | 隔离世界才能用 `chrome.runtime.getURL`；只负责注入 `@font-face` |
| 可访问资源 | `fonts/*` 限 educoder | 页面用扩展内字体文件（woff2） |
| 弹窗 | `popup.html` + `popup.js` | 三个开关 + 主题二级菜单；通过 `chrome.scripting.executeScript({world:"MAIN"})` 与页面通信 |

**重要约束**：Edge 已禁用命令行 `--load-extension` 加载扩展，所以自动化测试不能直接装扩展，改用 CDP 注入脚本模拟 `document_start`（见第 7 节）。

## 3. 状态与存储键（页面域 localStorage）

| 键 | 含义 | 默认 |
|---|---|---|
| `fuckTougeTheme` | 主题开关 | `on`（默认开；`"off"` 关闭） |
| `fuckTougeThemeName` | 主题选择：`catppuccin` / `github` | `catppuccin` |
| `fuckTougeFont` | 字体开关 | `off`（首次弹窗询问后写死） |
| `fuckTougeFontAsked` | 字体是否已询问（只问一次） | 无 |
| `fuckTougeCursor` | 光标平滑动画开关 | `off` |
| `fuckTougeUI` | **旧版遗留**（单开关），仅用于迁移兼容 | — |
| `fuckTougeAutoJumpAt`（sessionStorage） | 自动跳转时间戳**及类型**（`时间戳\|next` 或 `时间戳\|last`），跨整页刷新补提示（15s 内有效；兼容旧的纯时间戳格式） | — |

> 这些键在 educoder.net 域下；弹窗（扩展域）读不到，必须经 `executeScript` 调 `window.__fuckTougeUI`。

对外 API（挂在主页面上）：
```js
window.__fuckTougeUI.get()  // → { theme, font, themeName, cursor }
window.__fuckTougeUI.set(next) // 只处理传入的字段（局部更新），返回最新状态
```

## 4. 功能实现详解

### ① 剪贴板保护（4 个子机制，全部在 允许粘贴.js）

**背景**：头歌禁止粘贴/复制，并在你聚焦编辑器时往剪贴板写一个空格覆盖内容。

1. **拦截篡改**：给 `navigator.clipboard` 的实例属性打补丁：
   - `writeText`：长度 ≤2 或纯空白 → `Promise.reject(NotAllowedError)`，其余放行；
   - `write`：全部拒绝。
   用 `Object.defineProperty(configurable: true)` 覆盖（实例属性优先于原型）。

2. **按键直通**（window 捕获阶段）：
   - `Ctrl/Cmd + V`：`stopImmediatePropagation()`（阻止页面自己的拦截器），并开启 300ms 观察窗、清零撤销预算；
   - `Ctrl/Cmd + C/X`：同样放行（页面可能拦复制）；
   - 带 `Alt` 直接放行（避免误伤 AltGr 组合键）。

3. **粘贴回落**（window 捕获 `paste`）：
   - 每次粘贴重置 300ms 观察窗 + 撤销预算；
   - 若焦点在 `.monaco-editor` 内 → `preventDefault()`：不让浏览器把内容"打字式"插入（会触发自动缩进），改由 Monaco 自己的 paste 处理器走原生粘贴（多行格式正确）。

4. **删除撤销保护**：
   - `model.onDidChangeContent`：300ms 窗口内检测到**删除型变更**（`!c.text && c.rangeLength > 0`）且撤销次数 <3 → 30ms 后向编辑器 textarea 派发合成 `Ctrl+Z`（`keydown` + `keyCode: 90`）；
   - 目的：网页在粘贴后同步删除内容（约 10ms）时自动撤销回来；
   - 预算 3 次、每次删除后窗口再延 300ms，避免把用户自己的删除无限撤销。

5. **属性清理**：`onpaste/oncopy/oncut/ondrop/oncontextmenu` 属性 —— 启动清一次 + **每秒巡检**（页面可能动态加回来）。

### ② 自动下一关

**代码题**（庆祝弹层）：
- 观察对象：`.evaluate-result-container`（失败时不会出现这个容器）；
- 按钮文案表 `NEXT_LABELS`：`下一关 → next`、`最后一关 → last`、**`完成 → last`**（最后一关是测试题页时，按钮文字是「完成」）；匹配前做空白/零宽字符归一化；
- 只点**弹层内部**的按钮（页面工具栏的「下一关」永不触碰）；若按钮处于 disabled/aria-disabled 则**等待激活再点**（10s 后放弃），避免把点击浪费在禁用态上；点击动作为完整鼠标序列 `pointerdown → mousedown → pointerup → mouseup → click`；
- 弹层出现 3 秒还没有匹配按钮 → 提示「已经是最后一关了 😋」（每条弹层只提示一次，保守兜底）；
- 无可见弹层时重置标记（兼容弹层复用）；
- MutationObserver 观察整个 `document`（`childList+subtree`），**200ms 节流**；另有 1s 轮询兜底。

**选择题**（无编辑器页面）：
- 用户手动点「评测」（capture 阶段记录）→ 每 250ms 轮询该按钮：disabled→enabled 判定评测结束（有 1.5s 宽限；30s 超时放弃）；
- 结束后 300ms 点页面里可见的、非弹层内的「下一关」；没有 → 提示「已经是最后一关了」。

**跳转提示**：
- 点击后按按钮类型 toast：`下一关` →「已为您自动跳转至下一关 😋」；`最后一关` →「已经是最后一关了 😋」；
- 同时写 `sessionStorage.fuckTougeAutoJumpAt`（`时间戳|类型`），若跳转是整页刷新，落地脚本检测到 15s 内的标记就补一条**对应文案**的提示（5000ms 后清除标记；清除定时器会先 clear 再重设，避免连续跳转时误删新标记）。

### ③ 编辑器增强（主题 / 字体 / 语法着色 / 光标）

#### 3.0 拿到 Monaco 实例（三条路，全都用上）
头歌页面**先创建编辑器、后暴露 `window.Monaco`**，所以：
1. 在 `window.Monaco` 上定义 `defineProperty` 的 setter —— 页面赋值时立刻挂钩（**setter 里的调用必须 try/catch，异常会外泄到页面脚本**）；
2. `Monaco.editor.onDidCreateEditor` —— 收之后创建的编辑器；
3. **React fiber 反查**（`findEditors`）—— 对每个 `.monaco-editor` DOM 向上找 `__reactFiber$`，沿 `return` 上溯 ≤80 层、每层 hook 链 ≤50，命中 `v.current.instance.updateOptions` 即编辑器实例；用来收"挂钩之前就已经存在"的编辑器。
另有 1s 轮询兜底（页面 readyState complete 或 60s 后停）。

#### 3.1 主题系统
- 定义了 **4 套主题**（`UI_THEMES`）：Catppuccin Mocha/Latte、GitHub HC Dark/Light（配色从 GitHub 官方主题 v6.3.5 编译产物逐项提取，含高对比专属纯白/纯黑选区与荧光括号色）；
- 抽象成 2 个**主题选择**（`THEME_CHOICES`），每个带深/浅变体；`uiTheme(platformName)` 按平台的 `vs/vs-dark` 映射到对应变体，实现"跟随平台昼夜自动切换"；
- **接管 `Monaco.editor.setTheme`**：页面调 `'vs'` / `'vs-dark'` 时记录平台意图并转发为我们定义的变体（关闭主题时原样转发）；自己的应用走 `__ftOrigSetTheme` 直连，避免递归；
- `ensureDarkMode`（best-effort）：主题开启且判定平台是白背景时，自动点平台设置齿轮（`i.icon-shezhi9`）→ 在 `.tpi-code-setting` 面板把「显示模式」从"白色背景"切到"黑色背景"（Ant Design 下拉需 `mousedown`+`click`）→ 再点齿轮收起；只做一次（`__ftDarkChecked`）。

#### 3.2 字体（内置、仅英文）
- 内置三个 woff2（Regular/Bold/Italic，合计约 231KB），family 名 `Maple Mono Web`，由 `fonts.js` 注入 `@font-face`；
- 字体栈：`'Maple Mono NF CN', 'Maple Mono Web', 'Maple Mono', monospace` —— **本机装过 CN 版就优先用 CN（中文也变），否则内置版只替换英文/代码符号**；
- 应用方式：`editor.updateOptions({ fontFamily, fontLigatures, bracketPairColorization, guides })`；字体加载完 `document.fonts.ready` 后调 `Monaco.editor.remeasureFonts()`；
- 关闭时用**快照**（`orig`）还原原选项；快照在登记编辑器时读取（`readOrigOptions`）；
- 首次进入有编辑器的页面弹一次询问（「启用/暂不」），选择写入 `fuckTougeFont` + `fuckTougeFontAsked`，之后不再打扰，可在弹窗随时改。

#### 3.3 Java 语法着色（本项目最折腾的部分）
**问题**：内置 Java tokenizer 很粗——所有关键字都是 `keyword.xxx.java`；**类名/方法名/变量全是 `identifier.java`**，同色难分辨；且这份 Monaco **不支持语义着色**（`EditorOption` 里没有 `semanticHighlighting`，注册 provider 后从不被调用，实测 0 次）。

**方案**：用 Monarch **替换整个 Java tokenizer**（`setMonarchTokensProvider('java', JAVA_MONARCH(...))`）：
- 定义了完整的 Java 词法（注释/文档注释/字符串/字符/数字/注解/运算符/括号 + 状态机处理多行）；
- **smart 模式**（主题开启时）的启发式分类：
  - `if/for/...` → `keyword.control`；基本类型 → `keyword.primitive`；`true/false/null` → `keyword.constant`；`class/interface/...` → `keyword.declaration`；`package/import` → `keyword.import`；其余修饰符 → `keyword`；
  - 全大写词 → `constant`；大写开头 → `type.identifier`（类/类型）；小写且后面跟 `(` → `function`；其余 → `identifier`（变量的区分到此为止，没有真正的类型信息）；
- **plain 模式**（主题关闭时）退回"所有关键字一个色、所有标识符一个色"，尽量贴近平台原样。

**踩过的大坑**（务必记住）：
1. Monarch 定义**必须**包在 `{ tokenizer: { root: [...], ... } }` 里，否则报 `a language definition must define the 'tokenizer' attribute`；
2. **内置 Java 语法是异步装载的**：页面加载后才会注册，会**覆盖**我们抢先装的；而且它是走内部路径注册的，连包装 `setMonarchTokensProvider` 的公开方法都拦不住；
   → 解法：主题开启时在装载窗口内**重试安装**（`[400, 1200, 2500]ms`），并在 `hookEditorUI` / 主题切换时重装；同时仍保留对公开方法的包装（兜底）。

#### 3.4 光标手感
- `cursorBlinking: "smooth"`：**无条件默认开启**（纯视觉、无功能影响）；实测此版本支持 `blink/smooth/phase/expand/solid` 五档；
- `cursorSmoothCaretAnimation`：弹窗「光标动画」开关控制，**默认关**。此版本是**布尔 API**（只有开/关），开启后**打字时也会滑动**（拿不到 VS Code 的 `explicit` 档）；
- **快照分离**：字体用 `orig`、光标用 `cursorOrig` 分开存，避免"关字体"时把光标设置一起还原（曾经的设计缺陷，v2.1 修正）；
- 评估结论（备忘）：`smoothScrolling` 因有缓动延迟、非纯正向提升，**默认不开**。

### ④ 页面皮肤（无编辑器的页面）

**问题**：主题/字体依赖 Monaco 实例，选择题等无编辑器页面（题干、代码块、左栏任务区全是平台静态 HTML）不变，深浅割裂。

**方案**（纯 CSS，无 DOM 侵入）：
- 状态以属性挂在 `<html>` 上：`data-ft-skin="catppuccin|github"`（主题开关+主题名）与 `data-ft-font`（字体开关独立）；
- 注入 `<style id="ft-skin-style">`：两套 `--ft-*` 变量（同两套主题的深色配色）+ 规则覆盖平台骨架（左右面板、标签导航、题干 markdown、代码块 `pre.prettyprint` 及其 token 类、Ant radio/表格/按钮/分页器等）；
- 随 `applySkin()` 在初始化与三个 setter（主题开关/主题名/字体开关）中即时联动；
- 字体规则覆盖代码块与正文（v2.4.1 起）：`pre/code/kbd/samp/ol.linenums` + 正文容器内 `p/li/td/th/标题/链接/按钮/span`（排除 icon/anticon 与 div/i/input/textarea，护住平台图标字体与 Monaco 输入）。

**踩过的坑**：
1. `document_start` 注入时 `document.documentElement` 可能还是 `null` → `applySkin` 开头判空并 10ms 重试；
2. 平台把浅色值写在**内联样式**里（记录区 `div[style="background: rgb(255,255,255)"]`）→ 需 `!important` 覆盖；
3. 代码块隔行浅灰条来自 `pre.prettyprint ol.linenums li`（平台 rgb(238,238,238) 条纹）→ 统一置透明；
4. Ant 组件（表格/分页/按钮/skeleton）自带浅色底，逐一适配（thead th `!important`、分页选中用 accent 底）；
5. `html` 元素自身残留 #fafafa 背景（body 未覆盖处会露白）→ v2.4.1 给 `html[data-ft-skin]` 也设 `background: var(--ft-bg) !important`；
6. 正文字体被平台样式（`"Microsoft YaHei"` 等）显式指定 → v2.4.1 扩宽字体规则到正文元素才生效，同时护住 iconfont 与 Monaco。

**验证**：调试实例选择题页（`mvtb62kwi4hj`）数值断言 + 截图复核：两套皮肤变量正确、关主题后完全还原平台浅色、字体开关独立、代码页回归（编辑器 Catppuccin 正常共存）、代码块 2x 放大确认无残留浅条 ✅；v2.4.1 复测：`htmlBg` 与正文字体开/关联动正确（关字体回微软雅黑、图标字体始终 iconfont）✅。

**v2.4.2 补充**：作答容器 `ul.choose-container` 原为平台 `#1e1e1e`，会盖住主题底色 → 置透明（透出右栏 `--ft-bg`，与编辑器背景一致）；并统一 `resize-y-bar`/滚动条/`test-header`/`test-case-item`/`ghost-link` 等平台残留深色。

**v2.4.3 补充**：皮肤与字体统一加「答题页面」门槛（`isAnswerPage()`：路径须形如 `/tasks/{课程}/{章节}/{关卡}`）——主页、目录等页面不再应用任何皮肤/字体改动；并包装 `history.pushState/replaceState` + `popstate` 监听，SPA 内在主页 ↔ 答题页切换时即时挂上/摘掉皮肤。

### ⑤ 扩展弹窗（popup）
- 三个开关（主题/字体/光标动画）+「主题」下方二级菜单（Catppuccin / GitHub 高对比），关闭主题时菜单自动收起；
- 与页面通信：`chrome.tabs.query` 找活动标签 → 校验 educoder 域名 → `chrome.scripting.executeScript({ world: "MAIN", func, args })`；
- 推送时发送**完整状态** `{theme, font, themeName, cursor}`（服务端 `set` 支持局部更新，双保险）；
- 失败提示区分："不是头歌页面 / 页面未就绪（刷新后重试）/ 页面已刷新或不是头歌页面，请重试"。

### ⑥ 轻提示 toast
- 页面顶部居中，深色圆角、`pointer-events:none`、`z-index` 拉满；2.6s 后淡出销毁；只用于"已自动跳转 / 已经是最后一关"。

## 5. 头歌平台知识库（实测积累）

### 页面/DOM
| 对象 | 选择器 / 特征 | 备注 |
|---|---|---|
| 代码编辑器 | `.monaco-editor`（在 iframe 内） | 所以内容脚本要 `all_frames` |
| 评测按钮 | 文字 `评测`（原类名 `.btn-run___fh7pl` 是**哈希类名，会随平台构建变化，不可依赖**） | 评测中 `disabled` |

### 行为特性
- **课程实测关卡链**（Java入门 第五章 - 循环结构基础）：第5关 `g4oxl5jy2tqr`（编程）→ `zfkoylaenjq9` → `an8vh69rmbyz` → 最后一关 `mvtb62kwi4hj`（第8关 for循环测试题，**选择题页、无编辑器**）；最后一关的弹层按钮是 **「完成」**（`footer .tc > a.current`），不是「下一关」；

### 这份 Monaco 的版本特征（全是实测）
- 支持 `registerDocumentSemanticTokensProvider`，但**语义着色不生效**（无 `semanticHighlighting` 选项、provider 从不被调用）；

- Java tokenizer 产出的 token：`keyword.<词>.java`、`identifier.java`、`delimiter.java`（**运算符也叫 delimiter**）、`delimiter.parenthesis/curly/square/angle.java`、`string(.escape).java`、`number(.float/.hex).java`、`comment(.doc).java`、`annotation.java`。

## 7. 测试方法（CDP 自动化）

**为什么不能直接装扩展测试**：Edge 禁用了 `--load-extension`。所以用独立的调试档案 + CDP 注入源码，模拟 `document_start`。

**流程**：
```bash
# 1) 启动调试实例（独立档案，和真实浏览器隔离）
rm -f ~/.config/microsoft-edge-debug/Singleton*
setsid nohup /usr/bin/microsoft-edge-stable \
  --user-data-dir="$HOME/.config/microsoft-edge-debug" \
  --remote-debugging-port=9222 --restore-last-session >/tmp/opencode/edge-debug.log 2>&1 &

# 2) 用 /tmp/opencode/cdp.py（零依赖 CDP 客户端）：
#    新目标 → Page.addScriptToEvaluateOnNewDocument(源码) → Page.navigate(url)
#    → Runtime.evaluate 读状态/颜色 → Page.captureScreenshot 看渲染

# 3) 测完关掉调试实例
pgrep -f "microsoft-edge-d[e]bug" | xargs -r kill
```

**注意事项**：
- `addScriptToEvaluateOnNewDocument` **跨 WebSocket 会话会失效**：每次测试脚本要重新注入；
- 多个测试目标混在一起容易连错页面 → 每次都确认 `window.__fuckTouge` 版本；
- 验证语法用页面里的 `new Function(源码)`；验证颜色用 `getComputedStyle` 读取指定词的 span；
- `~/.config/microsoft-edge-debug/` 里的 localStorage 会保留，测试前想干净状态可以清掉；
- 调试实例用的是独立档案，动它不影响用户真实浏览器。

### 8.1 分享给别人的更新方式（解压扩展没有自动更新）

- 推荐流程：**解压新版到别处 → 用新版内容覆盖旧扩展文件夹（路径不变）→ 扩展页「重新加载」**；
- **不要**删旧文件夹/换新路径再加载（会重演"找不到扩展"，需要重新注册、重新固定图标）；
- 覆盖式更新的副作用：旧版存在、新版已删除的文件会残留（如 v1.8 的 6MB 中文包）——不影响运行，可手动清理；
- 版本校验：扩展页显示 manifest 的 version，更新后能看到变化；
- 为什么不做自动更新：解压（unpacked）扩展不支持 `update_url` 自托管更新（那需要签名 crx + 托管 XML，且 Windows/Edge 对店外安装有拦截），所以只能手动覆盖。

## 9. 已知限制与未来想法

- 语义着色不可用 → 类名/方法/变量的区分只能是启发式（大写→类型、`(`→方法、全大写→常量）；
- `cursorSmoothCaretAnimation` 无 `explicit` 档（打字也滑动）；想要"只在点击/方向键时滑"在这份 Monaco 上做不到；
- 内置字体只覆盖英文/代码符号；中文替换需用户自行安装 Maple Mono NF CN；
- 主题想做更多套（Dracula/One Dark 等）时：只需往 `UI_THEMES` + `THEME_CHOICES` 加条目，弹窗二级菜单加按钮（现有结构已支持扩展）；
- 若头歌将来升级 Monaco/换编辑器内核，优先检查：`window.Monaco` 是否还在、`.evaluate-result-container` 是否还在、图标类名是否变化；
- 自动下一关依赖"弹层出现=通过"的假设，若平台改版（例如失败也出现该容器）需要重新验证。
