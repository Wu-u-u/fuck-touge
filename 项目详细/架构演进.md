# 架构演进：从单账号串行到多 worker

> 记录当前阶段（几十账号、百级章节/天）的取舍，不是最终 SaaS 架构。

## 已落地

- 每个 worker 独立 `EDUAUTO_STATE_FILE`、`EDUAUTO_PORT`，不再共享全局 `state.json.running`。
- 端口从 9301–9399 动态租约，避免多个 launcher 撞端口；槽位/profile 也有文件锁。
- worker 结束后把 `names/logins/course_orders/slots` 合并回主 state，不覆盖主 `current`。
- 父进程捕获 Ctrl+C，终止 worker 进程组并释放锁，避免后台 Edge 残留。
- `worker` 子命令负责“槽位 + 指定课程 + run”，结束后关闭自己的 Edge。
- `parallel.py` 按 `--slots`、`--course`、`--jobs` 启动多个独立 Edge；默认 2，最多 3。
- worker state 位于 `state/runs/<run-id>/worker-<slot>.json`，结果位于同目录 `result-<slot>.json`。
- 章节失败/缺答案隔离：缺答案章记 `missing` 并继续后续章节。
- 预加载 target 认领串行化，避免多章同时进入时误关主线程页面。

## 暂不做

- 完整 SQLite 五表迁移：当前量级用每槽 JSON + TOML 答案即可；SQLite 留到 worker >4、需要跨机任务队列/lease 时。
- 4～8 个 Edge：平台冷却和同 IP 风控是主瓶颈，先 2～3 个账号级 worker。
- 自动换序重试、全量答案指纹：先实测选项顺序；不要用重试掩盖真实错误。
- Web 后台、分布式、K8s。

## 运行前提

- 每个槽位需要已登录；`parallel.py` 会复制主 `state.json` 的 slots/logins/names 到 `state/runs/<run-id>/worker-<slot>.json`。
- 同账号内部仍然串行评测；并行只跨账号。
