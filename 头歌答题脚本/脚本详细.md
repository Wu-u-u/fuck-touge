## 0. 一句话定位

一个跑在终端里的 **Python 半自动答题器**：用 CDP（Chrome DevTools Protocol）驱动一个专用副本 Edge 窗口，自动把标准答案档案里的代码填进头歌编辑器、点「评测」、借助 Fuck头歌 扩展自动跳关，整章刷完自动换下一章；任何一关失败就停下并提示。

**边界**：不绕过考试监考、不自动提交作业、不破解平台接口；只做人已经会做的重复劳动。

## 1. 运行形态与技术栈

| 项 | 值 | 说明 |
|---|---|---|
| 语言 | Python 3.14 | 只用标准库，零第三方依赖（`tomllib` 读档案、`socket` 手写 WebSocket） |
| 浏览器 | Microsoft Edge (Chromium 154) | 脚本自己拉起，带 `--remote-debugging-port=9222` |
| 协议 | CDP over WebSocket | `cdp.py` 自实现最小客户端（零依赖） |
| 副本档案 | 支持 1~99 档案槽（`state.json` 记忆） | 每槽一个独立登录；`browser N/new/Nnew` 管理 |
| 扩展复用 | `Fuck头歌` v2.3 | 脚本自动 `Extensions.loadUnpacked` 加载，复用其自动跳关与提示语 |

## 3. 总体架构与数据流

```
           ┌─────────────── 终端 ───────────────┐
           │  python3 答题.py run               │
           └───────────────┬────────────────────┘
                           │ CDP over WebSocket(9222)
                           ▼
           ┌──────── 专用副本 Edge 窗口 ─────────┐
           │  课堂页 ──点「开始学习」──▶ 任务页   │
           │      ▲                        │      │
           │      │                    Monaco API  │
           │      │                    setValue    │
           │      └────── 整章结束返回 ────┤      │
           │                               ▼      │
           │                    点「评测」→ 弹层   │
           │                    Fuck头歌 自动跳关   │
           └────────────────────────────────────────┘
```

主循环（`run` → `process_chapter`）：

1. 新开干净课堂页 → 打开该章详情页抓「关卡→通过状态」→ 再开干净课堂页；
2. 点该章「开始学习」→ 等待新任务标签页（拿到 homework_id）；
3. 不断点「上一关」回到第 1 关（`rewind_to_first`）；
4. 逐关：
   - 已通过（详情页状态）/档案 `skip` → 点工具栏「下一关」直接跳过；
   - 编程题 → 单文件：`Monaco.editor.getModels()[0].setValue(答案)`；多文件：逐文件点开写入（v0.9）；
   - 选择题 → 按题号点选选项（答案如 `"B"` 或 `["B","A","D"]`）；
   - 点「评测」→ `wait_outcome` 判定：**通过**（扩展自动跳下一关）/ **最后一关** / **未通过**（暂停）；
5. 最后一关通过 → 关闭本章标签页，换下一章；全部完成 → 打印汇总。

## 4. 答案档案格式（answers.toml 规范）

TOML，`tomllib` 直接读，无依赖。**章节顺序 = 作答顺序**。

**通用性设计（重要）**：档案里**只写答案，不写进度**——没有"已通过/跳过"的记录。
脚本运行时先抓章节详情页的通过状态，已通过的关卡自动跳过。
所以同一份档案可以给进度不同的人使用；`scan` 也不会往档案里写 `skip`。
章节会按名字里的中文数字（一、二、……十）**自动排序**，scan/harvest 写文件时都会重排。

```toml
version = 1

[[chapters]]
name = "Java语言基础（九）- 数组进阶"      # 必须与课堂卡片标题一致（空白会被归一化）
homework_id = "4155348"                    # scan 自动填，run 用它打开详情页

[[chapters.levels]]
name = "数组的复制"                        # 与任务页「第N关：xxx」一致；重名时以顺序为准
answer = '''
package step1;
...完整代码，原样粘贴（三引号内不转义）...
'''

[[chapters.levels]]
name = "选择题"
answer = ["B", "A", "D"]                   # 选择题：每题一个字母，按题号顺序

[[chapters.levels]]
name = "选择题（含多选）"
answer = ["C", "D", ["A", "B", "D"]]       # 多选：该题的答案是子列表

# 多文件关卡（一关有多个代码文件）：为每个文件写一个 files 子块
[[chapters.levels]]
name = "类与对象练习"
  [[chapters.levels.files]]
  path = "src/step4/Test.java"              # 路径必须和「代码文件」下拉里的一致
  answer = '''
  public class Test { ...完整代码... }
  '''
  [[chapters.levels.files]]
  path = "src/step4/WuMingFen.java"
  answer = '''
  package step4;
  ...完整代码...
  '''
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `chapters[].name` | ✓ | 章节（课堂卡片）名；匹配时会去掉空白/全角空格 |
| `chapters[].homework_id` | run 需要 | scan 自动填；也可以从任务页 URL `/tasks/课堂/<hid>/...` 手抄 |
| `levels[].name` | 建议 | 关卡名（仅校验用；重名关卡如八章两个「选择题」以**顺序**为准） |
| `levels[].answer` | run 需要 | 代码串（三引号）或选择题字母/嵌套列表 |
| `levels[].skip` | 否 | 手动逃生口：强制不跑这一关；**一般不需要**，别写进分享版档案 |
| `levels[].type` | 否 | 预留：`code` / `choice`；一般不填，运行时会自动识别页面类型 |
| `levels[].files` | 多文件关卡需要 | 子表数组：每项 `path`（文件路径）+ `answer`（完整代码）。单文件关卡**不用**，直接用 `levels[].answer` |
| `levels[].multi` | 否（自动） | 该关是否多代码文件关：`true`/`false`。scan/harvest 自动写，**不用手改**；旧档案缺省时 run 回退为运行时检测 |

**填答案要点**：
- 代码要写**完整文件**（含 package/import/类体），直接覆盖编辑器，不是只写 Begin-End 中间那段；
- `'''...'''` 字面量字符串原样保留换行；若代码里出现 `'''`（极罕见），改用 `"""..."""`；
- 选择题的每题选项数不固定（八章第 3 关 3 题、第 6 关 2 题），字母按题号从前到后填；
- **多文件关卡**（编辑器左上角有「代码文件」下拉）：每个文件写一个 `files` 子块，路径要和下拉里的完全一致。
  懒得手抄路径：已满分的关卡用 harvest 自动采集，未满分的关卡 run 会暂停并打印可直接粘贴的模板。
- **`multi` 字段不用自己填**（v0.9.3）：scan 生成骨架、harvest 采集时会自动标记每个代码关是否多文件；
  run 见到 `multi = false` 的关卡直接走单文件流程，不再开「代码文件」下拉检测。

档案校验已并入 `run`：开跑前（未加 `-y` 时在等待回车之前）按章打印每关的答案状态。

## 5. 功能实现详解

### 5.1 副本浏览器管理（`ensure_browser` / `launch_edge` / `classroom_page`）

- 端口探测：`http://127.0.0.1:9222/json/version`；没开就 `subprocess.Popen` 拉起 Edge：
  `--user-data-dir=<profile> --remote-debugging-port=9222 --disable-popup-blocking --no-first-run`；
- **扩展自动加载**：`Extensions.getExtensions` 查是否已装；没有则 `Extensions.loadUnpacked({path})`（Edge 154 实测可用）。
  这样 Fuck头歌 的「自动下一关 / 提示语」直接在副本里生效，且**原扩展文件零改动**；
- **档案槽位（v0.6）**：`browser 1~99` 记住并切换档案，`new` 每次全新，`Nnew` 清除该槽换全新。
- **登录检测与账号名（v0.9.4）**：`ensure_login` 每轮遍历所有 educoder 标签找登录信号（登录往往发生在别的标签，原课堂页 DOM 不会自己刷新）；成功后自动记录账号名（任务页 `.task-user-info` / 用户页「个人主页」邻域）到 `state.json.names`；`browser -ls` 可随时查看。
  映射存在 `state.json`（`slots` / `current` / `running`）：
  · `apply_current_profile()` 在每次命令启动时把「当前槽」写进配置，scan/run 自动沿用；
  · 槽 1 默认取 config 里的 profile（老档案/已登录），新槽建在 `~/.config/educoder-auto/slotN`；
  · 切换槽时若旧浏览器在跑：CDP `Browser.close` 关掉并等端口释放，再拉起新档案；
  · `running` 记录当前浏览器属于哪个槽，避免"连到别人档案"；
  · 分享文件夹前要删 `state.json`（避免带上发送者的档案路径）；
- **登录检测**：课堂页出现 `.task-user-info` 或「退出课堂」即视为已登录；否则提示用户在窗口里登录并轮询等待；
- **窗口尺寸防线（v0.7）**：连接后若窗口小于 1400×900 就最大化（启动参数也带 `--window-size=1600,1000`）。
  原因：窗口缩到 821×914 时，课堂页 1300 宽布局把卡片按钮挤出视口，点击坐标落在屏幕外直接失效；
  同时 `card_pos_js` / `click_expr` 改为取「元素与视口交集」的中心点，元素部分在屏幕外也能点到；
- **课堂页必须每次新建**：实测课堂列表页被 SPA 导航到详情页再返回后，React 点击会失效（点「开始学习」无反应），
  而全新标签页正常。因此 `classroom_page()` 每章都 `close_target(旧页) + create_target(新页)`，并等 `ant-spin` 遮罩消失。

### 5.2 scan（v0.9.12 起已并入 harvest）

`scan` 不再是独立步骤：**直接运行 `harvest`** 就会自动发现课堂章节、补骨架，并在有已满分关卡时采集答案（详见 §5.7）。
`scan` 子命令只保留一条兼容提示（提示已并入 `harvest` 后退出），老笔记里的 `scan -a` 不会再执行扫描、也不会报错崩掉。
骨架合并写入的细节（只追加缺的关卡尾巴、`tomllib` 校验后落盘）仍在 `eduauto/archive.py` 里。

### 5.3 run：逐关作答主循环

- 计划预览：列出每章「有答案/缺答案」的关卡；开跑前每章会先抓详情页状态，把**实际已通过**的关卡也视作跳过（可续跑）；
- **进入章节**：干净课堂页 → 点「开始学习」（真实鼠标事件 + 遮罩检测 + `elementFromPoint` 校验 + 最多 4 次重试）→ 等新标签页；
- **回到第 1 关**：`rewind_to_first` 反复点「上一关」直到 `第1关` 或没有上一关（不依赖任务密文，天然抗平台改动）；
- **写代码（整文件全覆盖 + 回读校验）**：
  `Monaco.editor.getModels()[0].setValue(完整代码)`——相当于全选后整段粘贴，替换编辑器里的一切内容；
  写入前先等编辑器内容稳定（平台会先塞占位代码，稍后才加载真实代码，约 1.5 秒无变化才算稳），
  写完立刻 `getValue()` 回读比对，不一致重试一次，仍不一致就报错暂停（防止只写进去一部分）。
  关键：Python 侧用 `json.dumps` 转义，JS 里不要手写 `\\n`（曾因此把字面 `\n` 写进编辑器导致 18 个编译错误）；
  写完不评测就不会上传，服务器上仍是旧代码；
- **选择题（单选/多选通吃）**：`.option` 是题目组，组内 `a.flex-container` 里是 `label + input`；
  按题号把答案字母换算成下标后点选。**关键：页面会回显历史勾选，而 checkbox 是点击切换**——
  直接点已勾选项会把它取消。所以逻辑是：多选先清掉"不在答案里"的已勾选项，再补勾缺少的
  （已勾的跳过）；radio 点目标即自动切换。最后核对每题勾选集合，不一致自动重试一次；
- **点评测**：先 DOM `.click()`（此前真实鼠标点击偶发被遮罩吞掉），同时装结果探针；10 秒没动静再补一次真实鼠标点击；
- **写代码（多文件关卡，v0.9；v0.9.3 提速）**：档案 `multi = false`（且无 `files`）的关卡**直接走上面的单文件流程、不开下拉**；
  否则才读「代码文件」下拉里的文件数——
  · 只有 1 个文件：就是上面的单文件逻辑；
  · 多个文件：逐文件「hover 打开下拉 → 真实鼠标点开文件 → 等平台新建的 model 稳定 → 整文件 setValue + 回读」，
    全部写完后**再逐文件点开核对一遍**（不一致会自动重写一轮，仍不一致就暂停），核对通过才点评测；
    档案没写 `files` 或某个文件答案为空 → 暂停，并把可直接粘贴的 `files` 模板打进日志。
  细节见「5.8 多代码文件关卡」。
- **计时日志（v0.9）**：每关用时（`本关用时 x 秒`）、每章用时与 run 总用时（`fmt_secs`，≥90 秒自动换算成分钟）
  都会打进日志，便于定位慢点。

### 5.4 评测结果判定（`click_eval` + `wait_outcome` + PROBE_JS）

评测结果有四类信号，优先级从高到低：

| 信号 | 含义 | 说明 |
|---|---|---|
| toast `已为您自动跳转至下一关 😋` | 通过且已跳关 | Fuck头歌 自己点的弹层；只作提示，以关卡变化为准 |
| toast `已经是最后一关了 😋` | 通过且是最后一关 | 扩展找不到下一关按钮 |
| `.evaluate-result-container` 可见 | 通过（弹层还在） | 扩展不在时脚本 1.5 秒后自己点掉 |
| `.ant-message-notice` 文案含 `评测未通过` | 未通过 | 日志里 `failMsgs` 计数增加；**不会**出现庆祝弹层 |

> 备注：头歌对选择题会给部分分、部分正确时也会弹庆祝弹层。用户确认实际使用时答案一定正确，
> 所以 v0.4 起**不做**「回详情页核对满分」的额外校验（那是平台行为）；脚本按弹层/提示照常继续。

**为什么加「结果探针」**：选择题评测是**秒出结果**的，扩展 200ms 就把弹层点掉、toast 只活 2.6 秒，
0.4 秒轮询可能整段错过（实测踩过：最后一关判定超时 150 秒）。
`PROBE_JS` 在页面里常驻一个 MutationObserver，把出现的 toast 文本和弹层次数记进 `window.__aaLog`，
每次点评测前重置；`wait_outcome` 同时读 DOM 实时状态与探针日志，瞬时信号也不丢。

**点评测前先确认按钮可点、点完要看到证据（v0.9.6）**：平台在评测后有一段时间冷却——按钮变灰（disabled）
可持续 30 秒以上，有时下一关的按钮还会带 `NN S` 倒计时。灰色按钮上 `.click()` 是**静默无效**的（不派发事件），
旧版因此出现过「假成功 → 静等 180 秒或被扩展假跳骗」的事故。现在 `click_eval` 先 `wait_eval_ready`
等按钮变回可点；点击后把「按钮被点灰」也当作评测已开始的证据；两次尝试仍无任何证据就返回 False，
由调用方暂停报错（不再无声继续）。

**两个必须记住的实现细节（都踩过坑）**：
1. **toast 按元素打标去重**：观察者只记录没打 `__aaSeen` 的 toast 元素；
   重置日志不会让"上一关残留的提示语"再次被计入。且 `已为您自动跳转至下一关` **只算通过提示**，
   必须等"关卡序号真的变了"才判定 `next`（否则最后一关会被上一关的提示骗）；
   `已经是最后一关了` 是终止信号，可直接判定 `last`。
2. **Python 列表的 `in` 是精确匹配**：`TOAST_LAST in toasts`（toasts 是 list）永远匹配不到
   带 emoji 的 toast 文本，必须 `" ".join(toasts)` 后再做子串判断。这个 bug 让最后一关空等 180 秒。

失败处理：`wait_outcome` 返回 `fail` → 立即暂停退出，**保留浏览器现场**（不清标签页）供排查；
重新 `run` 时已通过的关卡会被详情页状态自动跳过，天然续跑。

### 5.5 跳关与换章

- 跳关主通道是 Fuck头歌：通过后它点弹层「下一关 / 最后一关 / 完成」；脚本只观察，不抢点（扩展不在才兜底点）；
- 跳过已通过关卡：点工具栏「下一关」（真实鼠标点击 + 等待关卡序号变化）；
- 最后一关通过后：关闭本章标签页 → 回到主循环 → 新开干净课堂页处理下一章（顺序 = 档案顺序）；
- 全程不点「提交总结」：用户确认过，关卡全通后系统自动完成，提交动作留给用户。

### 5.6 失败暂停与续跑

- 任何 `die()`（未通过/超时/缺答案/找不到关卡）都会打印原因、保留浏览器窗口、退出码 2；
- 续跑：修好答案后重新 `run`，脚本抓详情页状态自动跳过**满分**关卡（`已通过`，或 `已提交` 且得分≥分值）；
  选择题若只拿到部分分（状态「已提交」但不满分）会被静默重做——不回详情页做运行时校验，
  只是在开跑时的状态扫描里顺带判断（用户确认实际使用答案一定正确，这是兜底）；
- 浏览器保持打开，用户可直接在窗口里查看错误详情（测试结果面板有编译错误/对比输出）。

### 5.7 辅助命令

- `browser`：只启动/检查副本浏览器 + 登录检测（v0.9.4：多标签检测；登录后自动记录账号名）；`-ls` 列出各槽账号名；
- `scan`（v0.9.12 起已并入 harvest，仅保留兼容提示）；
- `harvest`：**扫描 + 采集一体**（v0.9.12 合并 scan）：自动发现章节、缺骨架补骨架、有已满分关卡就采集答案并写回：
  · 命令后显式写了章节名、且该章节还不在档案里时，会**先自动扫描骨架再采集**（两步合一）；
  · 全通章节的「开始学习」会落到详情页，脚本自动点「查看实战/继续挑战/进入实训」进关卡；
  · **已满分代码关优先读「评测记录」**（v0.9.16：平台可能不回显已提交代码，编辑器只剩 Demo 模板）；
    记录读不到/也像模板时才回退编辑器；两者都无效则放弃采集，绝不把模板写进档案；
    弹窗路线由 v0.9.5 加固：关闭改为 X→ESC→按钮三级并必须确认关掉，关不掉直接报错暂停（防遮罩卡死）；
  · 选择题读勾选（多选题采成嵌套列表）；读编辑器前先等内容稳定，防止采到占位模板；
  · **多文件关卡**（v0.9）：逐文件点开采集（每点开一个文件，平台会新建 model），采回 `files` 子块；
  · 默认只填空答案，`-f/--force` 覆盖已有答案；
  · **按章即时写回**（v0.9.7）：每采完一章立刻写回档案，采集中途出任何意外都不丢已采数据；
    无法进入的章节（已截止、卡片只有「查看作品」）记录一行日志后跳过，继续采后面的章（不再直接退出）；
- `check`/`walk`（v0.9.2）：不再单独提供——档案校验看 `run` 开跑前的每关状态预览；`walk` 因从未使用已删除。

### 5.8 多代码文件关卡（v0.9）

**平台 UI 行为（全部实测）**：
- 编辑器左上角有「代码文件」下拉（触发器在含「代码文件」文本的工具栏项里）；
- 下拉是**懒渲染**：页面刚加载时 DOM 里没有菜单项，真实打开一次后才常驻（关闭时元素宽高为 0，可据此判断可见）；
- 下拉由 **hover 触发**（antd Dropdown）：打开前先把虚拟鼠标移到中性点再 hover 触发器——
  鼠标若本来就停在触发器上，重复的 mouseMoved 会被 Chrome 去重、不产生 mouseenter，菜单不会展开；
  后台标签页（`visibilityState !== 'visible'`）不响应 hover，会先 `Page.bringToFront` 再操作；
- 菜单项是 `div.ant-dropdown-menu-item`，文本就是文件路径（如 `src/step4/Test.java`）；
- **必须真实鼠标点击**菜单项：DOM `.click()` 虽然也会新建 model，但不走平台的切换逻辑
  （当前文件标记 `[class*="pathActive"]` 不更新）；
- 菜单可能因平台 re-render/自动保存**中途自己收起**：点击前会重新读一次菜单项、要求连续两次坐标稳定（<1.5px），
  并用 `elementFromPoint` 确认该坐标下仍是目标项；目标消失就作废本轮重试，**绝不点陈旧坐标**
  （否则会点穿到编辑器里）；
- 每次点击**未激活**的文件会新建一个 Monaco model（`inmemory://model/N`，编号递增），内容 = 该文件当前内容；
  **点已激活项是无操作** → 所以「编号最大的 model = 刚点开的文件」；
- 平台会持久化未评测的编辑（草稿）：文件内容刷新/重开页面后仍在，脚本写的就是这个草稿状态，评测时提交。

**脚本函数组（答题.py「多代码文件关卡支持」一节）**：
- `list_code_files(page)` → `(paths, active)`：打开下拉列全部文件与当前激活文件（单文件关卡返回 1 项）；
- `click_code_file(page, path)`：真实点击 + 等平台新建 model（最多重试 3 次；点前坐标稳定 + `elementFromPoint` 命中校验）；
- `_file_items` / `ensure_file_menu` / `close_file_menu`：下拉的读/开/关（hover 打开、`bringToFront`、移开鼠标关闭）；
- `read_saved_files(page, paths)`：逐文件采集（harvest 用）；
- `write_files(page, live_paths, entries)`：逐文件写入 + **全量二次核对**（不一致重写一轮，仍不一致报错暂停）；
- `wait_uri_settled` / `write_uri_code`：按 model uri 等稳定 / 写入 + 回读校验。

**命令行为**：
- `run`：文件数 >1 走 `write_files`；档案缺 `files` / 某文件答案为空 → 暂停并打印可直接粘贴的模板；
- `harvest`：多文件关卡逐文件采集，写回 `files` 子块（路径取下拉里的原样路径）；
- `scan`（v0.9.3）：生成骨架时顺带走查本章关卡，给代码关标 `multi`（多文件关同时生成空的 `files` 子块）；全通章节（只打开详情页）或走查中断时跳过标记，run 回退为运行时检测；
- `run`（开跑预览）：按文件显示答案状态（如 `2 个文件（Test.java✓，WuMingFen.java 缺）`）。

**已知限制**：两个文件不能重名（以路径区分，basename 相同时用完整路径匹配）；多文件关卡暂不支持 `skip` 与 files 混用。

### 6.2 行为特性

- 「开始学习」**新开标签页**；平台会记忆该实训"当前进度"，可能直接落在上次那一关（所以必须回退到第 1 关）；
- 已全通的章节点「开始学习」直接打开**详情页**；
- 列表页被导航后 React 交互会失效（详见 5.1）；
- 选择题评测**秒出**结果（没有容器编译过程），编程题一般 2~10 秒（首次可能要等沙箱启动，出现「服务启动完成」）；
- 评测有约 30 秒冷却（按钮倒计时），连续两关之间会被平台强制等待；脚本会自动等按钮恢复「评测」；
- 每章关卡可能重名（八章两个「选择题」），档案匹配以**关卡序号**为准；
- 头歌会趁编辑器聚焦往剪贴板写空格、粘贴后同步删内容——那是 Fuck头歌 的活；本脚本用 Monaco API 写入，不碰剪贴板。

### 6.4 踩坑记录（务必保留）

1. **鼠标点击可能被 ant-spin 遮罩吞掉** → 点击前等遮罩消失 + `elementFromPoint` 校验 + 重试；
2. **课堂列表页被导航后会"死"**（React 点不动）→ 每章用全新标签页；
3. **详情表格分批渲染** → 等行数达到卡片显示的总关卡数，否则会漏掉最后一关；
4. **选择题结果瞬逝**（秒出、扩展 200ms 点掉弹层）→ 页面内结果探针（MutationObserver）；
5. **上一关的 toast 会残留 2.6 秒** → 探针按元素打标去重；"已跳转"只当提示，以关卡变化为准；
6. **Python 列表 `in` 是精确匹配** → 子串判断前先 `" ".join(list)`；
7. **Python 注入 JS 的双重转义** → 统一 `json.dumps`，别手写 `\\n`；
8. **真实鼠标点击有时点不动评测按钮** → DOM `.click()` 为主，真实鼠标为兜底；
9. **同一章可能有关卡重名**（八章两个「选择题」）→ 档案匹配以关卡序号为准；
10. **选择题页面会回显历史勾选**，checkbox 点击是"切换"→ 必须先清掉不在答案里的勾选、再补勾（否则会反选）；
11. **工具栏「上一关/下一关」在页面刚加载时点击可能不生效** → 每方向最多重试 3 次；
12. **已全通的章节**点「开始学习」直接进详情页，不是任务页 → `enter_chapter` 两种都接受；
13. **窗口过窄会把按钮挤出视口**（821×914 实测）→ 自动最大化窗口 + 点击取「元素与视口交集」中心点；
14. **平台先塞占位代码、后加载真实代码** → 读写前等编辑器内容稳定（约 1.5 秒无变化）；
15. **部分关卡编辑器不回显已提交代码**（只剩模板）→ v0.9.5 起 harvest 编辑器优先、弹窗仅作回退，从「记录 → 查看代码」弹窗的新 model 读原文；
16. **详情表格可能只渲染出行、单元格为空** → 等"状态列有字"再判定，避免把已通过误判为未做；
17. **调试副本浏览器可能自己重启（会话恢复）** → 脚本每步都从 `/json` 重新找标签页，不缓存 target id 太久；浏览器死了 `ensure_browser` 会重新拉起；
18. **多文件关卡（v0.9）**：文件下拉懒渲染；DOM `.click()` 能新建 model 但**不走平台切换逻辑**（pathActive 不动）→ 必须真实鼠标点击；点未激活文件会新建 Monaco model（编号最大 = 刚点开的文件），点已激活项无操作；
19. **scan 用片段名会把章节名写歪（v0.9 修复）**：`scan "片段"` 现在写入卡片的完整标题，避免 `scan -a` 因名字不相等而重复追加骨架。
20. **评测冷却时按钮是灰的（v0.9.6）**：评测后按钮灰色（disabled）可持续 30 秒以上，有时下一关的按钮也带冷却（`NN S`）；灰色按钮上 `.click()` **静默无效**（不派发事件、但元素还在）→ 点击前先 `wait_eval_ready` 等它变回可点，否则会「假成功」。

## 9. 维护流程

1. 改代码前先手工核对导航（详情页 →「查看实战」→ 关卡页）；改完用一个"还有关卡没做"的档案槽真跑一章验证（失败会暂停并保留现场）；
2. 头歌改版时的排查顺序：课堂卡片按钮文本 → 任务页 URL 形态 → `.monaco-editor`/`window.Monaco` → `.evaluate-result-container` → toast 文案 → 详情表格列义；
3. 每次改动**必加一条记录到 `更新记录.md`**（同目录，最新在最上面）；实现细节变了再更新本文件；
4. 发布/迁移：整个 `头歌答题脚本/` 目录拷走即可；到新机器改 `config.toml` 的 `binary`、`profile`、`extension` 路径，首次运行登录一次头歌；
5. **红线**：不要改 `Fuck头歌` 源码来适配本脚本；不要在答案里写绕过平台校验的代码。

## 10. 已知限制与未来想法

- 多文件关卡**已支持**（v0.9，见 §5.8）：采集/填写/写后核对全通；v0.9.3 起 scan/harvest 自动写 `multi` 预标记，run 对 `multi = false` 关卡免检测提速；没标记的旧档案回退为运行时检测（重扫一次即可）；
- 选择题已支持单选/多选，答案正确时平台判满分；**填空/简答未覆盖**（当前课程没有）；
- `harvest` 只能采集**满分**关卡；部分得分的关卡采不了（采到的是错误答案），需要人工修正；
- 评测冷却：点一次后按钮灰色可持续 30 秒以上；v0.9.6 起脚本会自动等冷却结束再点评测，刷一章 6~8 关约需 5~10 分钟，属平台限制；
- 失败暂停后需要人工改答案再续跑（按需求就是这么设计的）；
- 平台若引入更严的反自动化（按键序列检测等），可把 setValue 换成「CDP 输入事件模拟粘贴」，接口已封装（`Input.dispatchKeyEvent`）；
- 未来可加：`status` 汇总命令、完成后桌面通知、答案档案用 `answer_file` 引用外部 .java 文件。
