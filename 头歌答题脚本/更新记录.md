### v0.8 · 2026-10-02 · 提速 + 采集可靠性修复（评测记录取代码）

**背景**
- 用户反馈：run 启动慢（开了一堆辅助标签页），进关后题也加载得慢；实测采集时还发现了采集到模板代码的问题。

**提速（run 启动明显变快）**
- 状态检查全程**复用一个标签页**（原来每章都新开课堂页 + 详情页，现在只导航不重开）；
- 只有真的要跑的章节才新开课堂页点「开始学习」；跑完随手关掉；
- 各步骤加了「→ 检查平台状态…」等进度提示，不再看起来卡住；
- 轮询间隔从 0.5~1s 缩到 0.3~0.4s，新标签页等待、课堂页就绪等待都更快。

**采集/稳定性修复（都是实测撞出来的）**
1. **状态表可能只渲染了行、单元格还是空的**：现在要求"状态列有内容"才判定读完，
   避免把已通过关卡误判为未做（会导致整章重做）；
2. **平台会先塞占位代码再加载真实代码**：读/写编辑器前先等内容稳定（约 1.5 秒无变化），
   防止采集到模板、或写完被平台覆盖；
3. **有些关卡编辑器不回显已提交代码**（实测五章第 5 关只剩 `public class Demo` 模板）：
   harvest 改为**优先从「记录」里最近一次"评测通过"的「查看代码」弹窗读取**——
   该弹窗会新建一个 Monaco model，直接读完整原文（避免抓带行号/&nbsp;的展示文本），
   读不到再退回编辑器内容。采集标注会显示来源（评测记录/编辑器）。

**验证（真实采集与作答）**
- 五章重新采集：第 5 关从评测记录拿到 358 字符真实代码（原先是 185 字符模板）✅
- slot 2 账号的五章：跳过 1~4，作答 5（代码）/6（选择）/7（代码）/8（选择）全部通过，
  五章 8/8 完成 ✅

**影响文件**

### v0.7 · 2026-10-02 · harvest 自动补骨架 + 章节排序 + 窗口/点击修复

**背景**
- 用户要采集已做完的（非已截止）章节答案，并希望档案里的章节按顺序排好；
- 实测采集五、七章时撞到两个环境问题。

**改动**
1. **harvest 自动补骨架**：`harvest --chapter "还没扫过的章节"` 会先自动扫描生成骨架，再采集答案，
   不用先 scan 再 harvest 两步（仅对显式 `--chapter` 生效；`--all` 仍只处理档案里已有章节）。
2. **章节自动排序**：`sort_chapter_blocks()` 按章节名里的中文数字（一、二、……十）重排章节块；
   scan/harvest 写文件时自动排序，只挪块不改块内内容。现有档案已重排为 五、七、八、九、十。
3. **窗口自适应**：`ensure_window_size()` 连接后若窗口小于 1400×900 就最大化；
   启动参数也加 `--window-size=1600,1000`。
   （原因：副本窗口被缩到 821×914 后，课堂页 1300 宽布局把卡片按钮挤到视口外，
   `elementFromPoint` 返回 null，点击全部失效。）
4. **点击坐标收进视口**：`card_pos_js` 与 `click_expr` 改为取「元素与视口交集」的中心点，
   元素部分在屏幕外也能点到；配合 `scrollIntoView({inline:'center'})`。

**验证（真实采集）**
- `harvest --chapter 五 --chapter 七`：自动扫描 8+4 关 → 采集代码题 8 关、选择题 4 关（含 3 题多选：
  `[["B"],["C"],["B"]]`）→ 全部写回 ✅
- 采集后档案顺序：五、七、八、九、十；`check` 全部有答案 ✅

**影响文件**
- `答题.py`、`answers.toml`、`使用教程.txt`、`脚本详细.md`、`更新记录.md`

### v0.6 · 2026-10-02 · 浏览器档案槽位（多账号）

**需求**
- `browser` 后面加数字：`1` 记住并切到 1 号档案（1 号默认=现有已登录档案），`2/3/4/5…` 各记一个账号；
- `browser new` 每次都开全新档案；`browser 1new` 清除 1 号记忆、换全新档案启动。

**改动**
- 新增 `state.json`：记录 `slots`（槽→档案路径）、`current`（当前槽）、`running`（当前浏览器属于哪个槽）；
- `browser 1~99`：槽 1 默认取 config 里的档案；新槽建在 `~/.config/educoder-auto/slotN`（需登录一次）；
- `browser new`：每次新建 `guest-<时间戳>` 档案并记为当前；`browser Nnew`：清除 N 槽、换全新档案
  （旧目录不删，输出里给出旧路径）；
- 槽位切换：若旧槽浏览器还开着，用 CDP `Browser.close` 关闭并等端口释放，再拉起新槽；
  `ensure_browser` 只会在端口活着且 `running==current` 时复用，避免连错档案；
- 其它命令（scan/run/harvest/walk）启动时自动应用「当前槽」的档案；
- 修复实现过程中发现的 bug：切换槽时关闭旧浏览器后漏了"启动新档案"（会直接连端口报错），已补上并加重连重试。

**验证**
- `browser 1`：现有档案记为槽 1 并复用 ✅
- `browser 2`：新建槽 2、自动关旧开新、等登录 ✅
- `browser 2new`：槽 2 换全新时间戳档案，旧档案保留 ✅
- `browser new`：全新 guest 档案、记为当前 ✅
- `browser 1`：从 new 切回槽 1，自动关旧开新、登录态正常 ✅

**影响文件**
- `答题.py`、`cdp.py`、`使用教程.txt`、`脚本详细.md`、`更新记录.md`（新增 `state.json` 运行产物）

### v0.5 · 2026-10-02 · 多选题反选修复 + 跳关点击重试 + 终端全流程演示（八章 6/6）

**背景**
- 用户要求开终端把所有命令完整跑一遍看效果，并认为答案已填好。
- 演示时真实撞出两个 bug：多选题勾选被"反选"、工具栏跳关点击偶发不生效。

**修复**
1. **多选题（checkbox）反选**：页面会回显历史勾选，而 checkbox 点击是"切换"——
   直接点已勾选项会取消它（演示中 ABCD 被点成只剩 C）。
   修复：先清掉"不在答案里"的已勾选项，再补勾缺少的（已勾的跳过）；radio 点目标即切换；
   最后核对每题勾选集合，不一致自动重试一次。
2. **工具栏「上一关/下一关」点击重试**：页面刚加载时点击可能不生效（演示中"跳过第2关"卡住）。
   修复：每个方向最多重试 3 次、每次 20 秒等待，失败才暂停。
3. 写代码/点选项的运行时异常纳入优雅暂停（此前会抛栈退出）。

**演示与验证（真实评测）**
- 终端依次演示 `-h / check / browser / scan / walk / harvest / run / 再 run` 全部正常；
- `harvest`（临时档案）：采集 4 关满分代码，写回空答案 1 关；已有答案提示"未覆盖"；部分分选择题正确跳过；
- **八章从 4/6 刷到 6/6 全部满分**：通过三次提交的得分反推出第 3 关正确组合（第1题 C、第2题 D、
  第3题 ABCD 全选，各 5 分），实测 15/15；
- 档案最终答案：八-3 = `["C", "D", ["A", "B", "C", "D"]]`，八-6 = `["C", "B"]`。

### v0.2 · 2026-10-02 · 通用档案 + 完整实测 + 四个 bug 修复

**背景**
- 用户提出：**答案档案要通用**——不要记录"哪些关卡已通过/要跳过"（没有 skip 字段），
  由脚本运行时查详情页状态自动跳过；这样同一份档案可以给进度不同的人用。

**改动**
- `scan` 不再生成 `skip = true`：档案只保留「章节顺序 + homework_id + 每关答案」；
  跳过逻辑 100% 由运行时详情页状态（`已通过`/`已提交`）决定；`skip` 仅保留为用户手动逃生口；
- 选择题支持**多选题**（checkbox）：写法 `answer = ["C", "D", ["A", "B", "D"]]`
  （外层每题一项，多选答案是子列表）；
- 修复下列 4 个实测 bug；文档同步更新。

**修复的 bug（都是真实跑出来的）**
1. **上一关提示语残留骗过最后一关**：扩展的「已为您自动跳转至下一关 😋」在切关后还能活 2.6 秒，
   下一关（尤其最后一关）会被误判为"还有下一关"。
   修复：结果探针给每个 toast 元素打 `__aaSeen` 标记，重置日志不会重复计数；
   且「已跳转」提示不再作为最终信号，必须等"关卡真的变了"；只有「已经是最后一关了」可直接判定 last。
2. **Python 列表 `in` 语义坑**：`TOAST_LAST in toasts` 对列表是**精确匹配**而非子串匹配，
   导致最后一关提示存在却判定超时（等了 180 秒）。
   修复：先 `" ".join(toasts)` 再子串判断。
3. **课堂列表页导航后 React 点击失效**：访问过详情页再返回，卡片按钮点不动。
   修复：每章都用全新课堂标签页（`classroom_page(old=...)`），旧的顺手关掉。
4. **ant-spin 遮罩吞点击 + 详情表格分批渲染**：
   修复：点「开始学习」前等遮罩消失 + `elementFromPoint` 校验 + 最多 4 次重试；
   抓详情表格时按课堂卡片 `x/y` 等行数补齐（否则八章会漏掉第 6 关）。

**另外处理**
- 同名关卡：八章有两个「选择题」、名字匹配会撞车 → 档案匹配改为**以关卡序号为准**，名字仅作校验；
- 注入 JS 的转义：统一 `json.dumps`，避免把字面 `\n` 写进编辑器（曾导致 18 个编译错误）。

**验证（真实评测，全绿）**
- 九章 5 关全通过；失败路径实测：错误答案 →「评测未通过」→ 暂停并保留现场，恢复后自动跳过已通过关卡；
- 八章 6 关全通过（含 3 题含多选的选择题；最后一关是选择题，收尾正常）；
- 十章 8 关全通过（含多选 BDE；最后一关为编程题，"最后一关"收尾正常）；
- 全程档案无 `skip` 字段：补跑时分别自动跳过 5 关/6 关，通用性验证通过。

**影响文件**
- `答题.py`、`answers.toml`、`脚本详细.md`、`更新记录.md`（新增）
