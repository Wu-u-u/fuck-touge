================================================
 头歌自动答题脚本 · 使用教程（详细版）
================================================

【一、先搞懂 4 个东西】

1. 答题.py
   主程序（命令行入口）。你在终端里敲的各种命令都是它。
   具体流程在 eduauto/ 目录里按层分开（配置 / 浏览器 / 关卡 / 编辑器 / 答案 / 流程），
   升级或迁移时整个文件夹一起带走即可。

2. 专用副本浏览器
   脚本会自动拉起一个独立的 Edge 窗口（和你平时用的 Edge 隔离）。
   支持多个「档案槽」：1 号、2 号……每个槽有自己的登录状态（=不同账号），
   脚本会记住"当前槽"，之后 harvest/run 都用它。详见命令详解里的 browser。
   窗口被关掉也没关系，下次运行命令会自动重新打开。

3. answers.toml（答案档案）
   唯一需要你动手编辑的文件。里面记录：
     · 章节顺序（[[chapters]]，含章节名和 homework_id）
     · 每关的名字和答案（[[chapters.levels]]）
   它不记录任何人的答题进度，所以同一份档案可以给同学共用。

4. Fuck头歌 扩展
   脚本会自动把它装进副本浏览器（你也可以完全不管这事）。
   它的作用是：答对弹出庆祝弹层后自动点「下一关 / 完成」，
   脚本则读取它的提示语（"已为您自动跳转至下一关 😋"）来判断结果。

整个流程一句话：
   你填好答案  →  脚本把答案写进头歌编辑器  →  点「评测」  →  扩展自动跳关  →  继续下一关。


【二、命令总览】

命令        一句话                         什么时候用
--------    ----------------------------   ------------------------------
browser     启动/检查副本浏览器            第一次用，或浏览器被关了
harvest     扫描并采集答案（缺骨架自动补） 新章节 / 要把已做完的答案收进档案时（已截止章节自动跳过）
run         正式自动答题                  开始刷题（最常用；开跑前会先列出每关答案状态）

所有命令的固定格式：
    python3 答题.py <命令> [参数]

章节参数直接写在命令后（可写多个、可用名称片段；v0.9.8 起，如果一个短名同时命中多个章节，会列出候选问你选哪个），例如：
    python3 答题.py run -y 五 七          # 只刷五、七两章
常用短选项：-y=不询问直接开始  -f=覆盖已有答案（重采）；
旧的 --chapter 写法仍可用（等价于位置参数）。

先进入脚本目录（每次开终端都要）：
    cd /home/wu/头歌系列开发-我的第一个项目/fuck-touge/头歌答题脚本


【三、命令详解】

────────────────────────────────────────
◆ browser —— 启动/检查副本浏览器（支持多账号档案槽）
────────────────────────────────────────
命令：
  python3 答题.py browser          # 用"当前记住的槽"打开/复用浏览器
  python3 答题.py browser 1        # 切到 1 号档案，并记住它（1 号默认=现有的已登录档案）
  python3 答题.py browser 2        # 切到 2 号档案，并记住它（新槽=干净档案，需登录一次）
  python3 答题.py browser 3        # 3~99 同理，每个槽相当于一个独立账号
  python3 答题.py browser new      # 每次都开一个全新档案（每次都是干干净净的）
  python3 答题.py browser 2new     # 清除 2 号的记忆，给 2 号换一个全新档案
  python3 答题.py browser -ls      # 列出每个档案槽登录的账号名（浏览器在跑时实时刷新）
                                    # （旧档案不会删；1new、3new……同理）

作用：
  · 槽位会记住在 state.json 里；下次直接 python3 答题.py run 就沿用"当前槽"；
  · 切换槽位时，如果旧的浏览器还开着，脚本会自动关掉它再开新槽的浏览器；
  · 新槽第一次打开会要求登录（在那个窗口里登录一次，之后这个槽就记住这个账号）；
  · 自动把 Fuck头歌 扩展装进每个槽。

会改什么：打开/关闭浏览器、更新 state.json；不动答案档案、不动头歌数据。
什么时候用：
  · 第一次用（跑一次 browser 1，把现有档案记为 1 号并登录）；账号名会自动记录，随时可用 browser -ls 查看；
  · 多个头歌账号（2、3、4……各登录各的）；
  · 想从零开始（new / 2new）。

成功的样子：
  ✓ 副本浏览器就绪，已记住档案槽「1」，之后 harvest/run 都会用它。

注意：分享文件夹给同学前，把 state.json 删掉（否则对方会看到你的档案路径）。

────────────────────────────────────────
◆ scan（v0.9.12 起已并入 harvest）
────────────────────────────────────────
scan 不再是独立命令：
    python3 答题.py harvest          # 自动发现章节：缺骨架就补骨架，有已满分关卡就采集答案

老的 `scan` / `scan -a` 仍然可以输入，但只会打一行提示（不会执行扫描，也不会报错）。

────────────────────────────────────────
◆ harvest —— 扫描 + 采集：缺骨架补骨架，已做完的答案写回档案
────────────────────────────────────────
命令：
  python3 答题.py harvest "章节名"    # 只处理指定章节（可写多个）
  python3 答题.py harvest             # 处理课堂里的全部章节（自动发现）
  python3 答题.py harvest -f          # 覆盖档案里已有的答案

作用：
  · 只挑平台上"已经拿到满分"的关卡（没满分的会跳过，因为采到的是错的）；
  · 代码题：优先直接读编辑器里的内容（默认它保存的就是对的，而且读得快）；
    编辑器是空的才退回「记录」里的「查看代码」弹窗读取；
    注意：个别关卡编辑器不回显已提交代码（只剩模板）——这种关卡采完最好人工核对一下；
  · 选择题：把当时勾选的选项采回来（多选题自动采成子列表）；
  · 多文件关卡（一关里有多个代码文件）：自动逐个文件采集，写回每个文件的完整代码；
  · 写回 answers.toml：默认只填空着的 answer，已有答案不动（防止覆盖你写的东西；v0.9.9 起，已有答案的关卡连采集都跳过，-f 强制重采）；
  · 采集是**按章即时写回**的（v0.9.7）：每采完一章立刻保存档案，中途遇到问题也不会把已采到的内容弄丢；
  · 已截止/无法进入的章节（卡片上只有「查看作品」）会提示后**跳过**（harvest 和 run 都一样），不影响其他章节；
  · **档案里没有的章节会自动先扫一遍骨架再采集**（不用先 scan）；档案不存在时会自动创建。
  · v0.9.12 起 harvest = 扫描 + 采集一体：新章节会自动补骨架；已满分答案都齐的章节整章跳过；
    已截止章节（只有「查看作品」）只提示，不建骨架、不采集。

会改什么：只改 answers.toml（填空/覆盖答案），不会动平台上的内容。
什么时候用：
  · 你自己已经手动做完了一些题，想把答案整理成可复用的档案；
  · 想把自己做完的档案分享给同学，让同学直接 run。

输出怎么读：
  已满分关卡：[1, 2, 4, 5]
  ✓ 第1关「初识数组」：323 字符          ← 成功采集到
  ! 「二维数组」已有答案，未覆盖          ← 没覆盖，想覆盖加 -f
  ✓ 已写回答案档案                        ← 写文件成功

注意：没满分的关卡采不了（比如选择题只对一半），脚本会跳过并提示。

────────────────────────────────────────
◆ run —— 正式自动答题（主力命令）
────────────────────────────────────────
命令：
  python3 答题.py run                    # 按档案顺序刷所有章节（会先问一次，回车开始）
  python3 答题.py run -y                 # 不询问，直接开始（推荐日常用）
  python3 答题.py run -y "章节名"         # 只刷指定章节（可多个，如 run -y 五 七）

作用（按顺序）：
  1. 读 answers.toml；
  2. 对每个章节：
       a. 打开章节详情页，读每关的得分/状态；
       b. 已经满分的关卡 → 自动跳过；
       c. 没满分的关卡 → 按档案里的答案作答：
            · 代码题：整文件覆盖写入代码，写完回读校验；
            · 选择题：按字母点选（多选会先清掉多余勾选再补勾）；
       d. 点「评测」→ 等结果：
            · 通过 → 扩展自动点「下一关」，继续下一关；
            · 最后一关 → 扩展提示"已经是最后一关了"，本章结束；
            · 未通过 → 立即暂停，浏览器停在那关给你看；
       e. 本章结束 → 自动回课堂页，处理下一章。

会改什么：
  · 会真实提交答案（点评测 = 提交）；
  · 不改 answers.toml，不改课堂里其它数据；
  · 不会点"提交总结/交作业"。

什么时候用：答案填好之后的日常刷题。
输出怎么读（关键几行）：
  第1关 初识数组：跳过（已通过）          ← 平台上满分了，省一次评测
  第3关 选择题：作答
    已选择：[{q:1, letters:[C]}, ...]（勾选数已核对）
    点「评测」…
    结果：next（页面已跳转）              ← 通过，已去下一关
  结果：last（已经是最后一关了）           ← 本章最后一关通过，收工
  ✗ 第5关 … 评测未通过，已暂停            ← 失败，处理见"场景 3"

退出码（脚本给终端的状态码）：0=全部正常；2=中途暂停/出错。


【四、输出术语对照表】

  ✓ Fuck头歌 已加载（版本以实际为准）   扩展已装进副本浏览器，自动跳关有保障
  已满分，运行时会自动跳过      平台状态扫描结果：这关不用跑
  跳过（已通过）                run 时又检查了一次，确实满分，跳过
  作答                         这关要写答案并评测
  已整文件覆盖写入并校验通过    代码已整文件覆盖 + 回读一致
  检测到 N 个代码文件…          这关是多文件关卡，脚本会逐个文件处理
  ✓ 核对 src/…：平台状态与档案一致  多文件写入后的二次核对通过（保险）
  已选择：…（勾选数已核对）     选择题已点好，且数量对得上
  结果：next                   评测通过，已到下一关
  结果：last                   最后一关通过，本章结束
  结果：fail / timeout         没通过 / 等结果超时 → 脚本暂停
  已暂停                       停下来了，浏览器保留现场，看提示改答案再 run


【五、config.toml 每个字段】

  [edge]
  binary    = 浏览器可执行文件路径（默认 /usr/bin/microsoft-edge-stable）
  profile   = 副本浏览器的档案目录（登录状态、扩展都存这里）
              想换新档案/新账号：改成一个新路径，下次运行会要求重新登录
  port      = 调试端口（默认 9222，一般不用改）
  extension = Fuck头歌 扩展文件夹路径（脚本自动装载它）
  classroom = 你们班的课堂-实训作业列表页地址
              同学的课堂不同，改这一行即可

  [run]
  answers    = 答案档案路径（默认 answers.toml）
  eval_timeout  = 单次评测最多等多少秒（默认 180）
  level_timeout = 单关页面加载/跳转最多等多少秒（默认 60）

  各命令还可以临时指定配置文件：
    python3 答题.py -c 别的配置.toml run -y


【六、answers.toml 怎么写】

结构长这样（一个章节 + 若干关卡）：

  [[chapters]]
  name = "Java语言基础（八）- 数组基础"     # 章节名，必须和课堂卡片一致
  homework_id = "4155345"                    # scan 自动填，不用管

  [[chapters.levels]]
  name = "初识数组"                          # 关卡名，scan 自动填
  answer = '''
  package step1;
  ...完整代码原样粘贴...
  '''

  [[chapters.levels]]
  name = "选择题"
  answer = ["C", "D", ["A", "B", "C", "D"]]

  # 多文件关卡：一关有多个代码文件时，每个文件写一个 files 子块
  [[chapters.levels]]
  name = "类与对象练习"
    [[chapters.levels.files]]
    path = "src/step4/Test.java"
    answer = '''
    ...Test.java 的完整代码...
    '''
    [[chapters.levels.files]]
    path = "src/step4/WuMingFen.java"
    answer = '''
    ...WuMingFen.java 的完整代码...
    '''

写法规则：
  · 代码题 = 完整文件（含 package/import/类体），用三个单引号包住；
    不要只贴 Begin-End 中间那段。
  · 选择题 = 选项字母，按题号顺序：
      1 题：            answer = "B"
      3 题单选：         answer = ["B", "A", "D"]
      第 1 题 C、第 2 题多选 ABD： answer = ["C", ["A", "B", "D"]]
  · 多文件关卡（编辑器左上角有「代码文件」下拉）：不用 answer，改用 files 子块，
    每个文件一个；path 要和在「代码文件」下拉里看到的一模一样。
    路径不用自己抄：已满分的关用 harvest 采集；没满分的关 run 到它会暂停，
    并把可以直接粘贴的模板打印出来，照着填就行。
  · 每个代码关还带一个 multi = true/false 标记（scan/harvest 自动写入，不用手改）：
    run 看到 multi = false 的直接按单文件处理，不再逐关做检测（这就是它提速的原因）。
  · 已满分的关卡不用填（运行时自动跳过）。
  · 空着的 answer = "" 会被 run 视为"缺答案"，跑到那关会暂停提醒你。
  · 不想跑某关：把那关的 answer 留着空也行（会暂停），或删掉整关条目。


【七、典型场景剧本】

◆ 场景 1：第一次使用
     cd /home/wu/头歌系列开发-我的第一个项目/fuck-touge/头歌答题脚本
     python3 答题.py browser          # 弹窗，没登录就登录一次
     python3 答题.py harvest           # 自动发现章节、补骨架并采集答案
     编辑 answers.toml 填答案
     python3 答题.py run              # 先列出每关答案状态，回车开跑

◆ 场景 2：日常（答案早填好了）
     cd /home/wu/头歌系列开发-我的第一个项目/fuck-touge/头歌答题脚本
     python3 答题.py run -y

◆ 场景 3：跑到一半停了（未通过/超时/缺答案）
     看终端最后几行提示 → 浏览器停在那一关 → 对照错误详情改 answers.toml
     → 再 python3 答题.py run -y（已满分的关会自动跳过，只重做没过的）

◆ 场景 4：我已经手动做完一些题，想导出答案
     python3 答题.py harvest "章节名"
     · 章节还没扫过也没关系：harvest 会自动先扫骨架再采集
     · 把已经做完的每章名都写上就行（已截止的章节不用管，也点不进去）
     · 想覆盖档案里已有的旧答案，加 -f
     例子（一次采集两章）：
       python3 答题.py harvest "Java语言基础（五）- 循环结构基础" "Java语言基础（七）- String类"

◆ 场景 5：多个头歌账号（档案槽）
     python3 答题.py browser 1        # 1 号账号（默认就是你原来登录的那个档案）
     python3 答题.py browser 2        # 切到 2 号：新窗口，登录另一个账号
     python3 答题.py run -y           # 之后 run 一直用"当前槽"（此时是 2 号）
     python3 答题.py browser 1        # 想切回 1 号：自动关掉 2 号的窗口，开 1 号
     记忆存在 state.json 里；1new~99new 可把某个槽重置为全新档案。

◆ 场景 6：分享给同学
     把整个「头歌答题脚本」文件夹拷给他
     先删掉 state.json（避免带上你的档案路径和槽位记忆）
     他改 config.toml 的 classroom（如果是不同课堂）
     他先 python3 答题.py browser 1 登录自己的账号
     然后 python3 答题.py run -y（档案里已有答案，直接刷）

◆ 场景 7：换账号 / 换电脑
     换账号：用档案槽（browser 2 开新槽登录），或把某槽 2new 重置
     换电脑：拷文件夹、删 state.json，改 config.toml 的 binary / classroom 路径


【八、常见疑问】

Q：跑一章要多久？
A：平台两次评测之间有约 30 秒冷却，一章 6~8 关大约 5~10 分钟，属正常。
   run 启动时会先逐章检查平台状态（共用一个标签页，不会开一堆新页），
   已经满分的章节会快速跳过；某一关本身加载慢是头歌服务器的问题，等它即可。

Q：为什么 run 一开始会先停一会儿？
A：它在逐章检查"哪些关卡已经满分"，这部分只导航不重开标签页；
   终端会打印「→ 检查平台状态…」等提示，不是卡死。

Q：脚本怎么把代码写进编辑器？
A：整文件覆盖：相当于全选后把 answer 里的完整代码粘贴进去，替换全部现有内容；
   写完立刻回读校验，不一致会自动重试，仍不一致就暂停。

Q：会重复评测已经通过的关卡吗？
A：不会。每章开始先读平台状态，满分的关卡直接跳过。

Q：脚本会自动提交作业吗？
A：不会。只负责刷关卡；题全做完后平台会自行结算。

Q：跑的时候我能去干别的吗？
A：可以，但别去手动点那个副本浏览器窗口，容易和脚本抢操作。

Q：支持哪些题型？
A：单选题、多选题、编程题。一关里有多个代码文件也能处理（编辑器左上角有「代码文件」下拉的那种）；
   填空/简答题暂不支持，遇到会停下提示。

Q：中途把副本浏览器关了会怎样？
A：脚本会报错暂停；重新运行命令会自动拉起浏览器，已满分的关自动跳过，继续刷。

Q：怎么用另一个头歌账号？
A：python3 答题.py browser 2 → 在弹出的新窗口里登录第二个账号；
   之后 run 就用 2 号。想切回去：python3 答题.py browser 1。

Q：怎么彻底重置某个账号的登录状态？
